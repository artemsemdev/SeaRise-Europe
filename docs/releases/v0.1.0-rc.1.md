# v0.1.0-rc.1 — Coastal Atlas demo prerelease

Date: 2026-10-02. Status: source-only demo prerelease, not the stable MVP.

This version brings the accepted coastal atlas and a source-bound private local
demonstration workflow into the default branch. Anyone can run the explicitly
labeled public fixture from a clean clone. Operators with separately provisioned,
verified CoCliCo inputs can prepare a read-only application candidate and serve
the real-local atlas on their own computer.

The [GitHub prerelease](https://github.com/artemsemdev/SeaRise-Europe/releases/tag/v0.1.0-rc.1)
contains source via GitHub's automatic ZIP/TAR archives. It includes committed
illustrative fixtures and operational documentation. It does not distribute
CoCliCo raster packages, local basemap archives, a sealed application candidate,
private candidate receipts, or real-data screenshots. No public hosted atlas is
qualified by this release.

## Added

- A European coastal atlas with city search, selected-point inspection, a
  synchronized year timeline, comparison, shared views, and mobile controls.
  The real-local source has six combinations: 2030 / 2050 / 2100 under CoCliCo
  SSP5-8.5 spring-high-tide conditions, with No additional defenses or High
  protection. Depth is reported in meters for a native 25 m model cell.
- Explicit illustrative-fixture and provisioned real-local editions behind the
  same browser interface. Real-local setup or transport failures never silently
  replace source results with synthetic values.
- Private candidate preflight, preparation, and loopback launch commands. A
  receipt binds the exact source revision, pinned tools, application SHA256
  inventory, and six external manifest/receipt identities. Candidate files are
  read-only and preparation refuses to overwrite an existing candidate.
- A candidate runbook covering local preparation, a short demonstration,
  acceptance checks, shutdown, and rollback to a matching source/app/data pair.

## Changed

- Cold map initialization now gives controls an earlier paint opportunity and
  limits high-density canvas allocation. The native scientific sampling and
  displayed layer selection retain their source meaning.
- CI can accept labeled fixture evidence for this local demo under the separate,
  temporary owner-approved performance exception. The raw 90-point performance
  failures remain visible; this is not a reduction of the public/MVP target.

## Fixed

- Bounded native raster connection queuing keeps real-local tiles available
  during rapid overview, reload, and zoom requests.
- Private atlas, basemap, inspection, and error responses remain `no-store`.
  Shutdown also reaps the raster child if startup is interrupted.
- The retained synthetic `/projections/` reference works in the sealed local
  launcher with verified static caching, exact manifest identities, strict byte
  ranges, and the application icon. Its data path remains separate from CoCliCo.
- Dependency patches address the npm advisories found during candidate
  preparation; the active supply-chain profile and SBOM reflect those updates.

## Known limitations

- This prerelease establishes neither full-source scientific qualification nor
  public hosting, dataset-publication approval, or the stable MVP definition of
  done. Historical evidence keeps its original scope. The AR6 reference in this
  local demo is explicitly synthetic.
- The temporary local-demo exception requires performance **at least 50 in each
  of three cold fixture audits**, **at least 90 in every other category**, and
  healthy rendering. It expires at **2026-10-16T00:00:00+02:00**, the start of
  16 October in Berlin. It qualifies fixture software evidence only. Expiry
  affects acceptance, not operation of an already prepared artifact.
- A fresh first visit to the retained synthetic reference may show an update
  authority warning before its installed worker controls a normal subsequent
  navigation. Activation followed by an ordinary reload verifies the exact
  controlling pair; no forced activation is introduced. Presentation follow-up
  is [#531](https://github.com/artemsemdev/SeaRise-Europe/issues/531). The native
  atlas does not use this offline mechanism.
- Startup verifies raster bodies and pins external metadata identities. Basemap
  archive/font/sprite bodies are not fully rehashed at every launch; provisioning
  integrity and served-byte/browser checks remain necessary. Candidate receipts
  are local integrity records, not signatures or scientific certification.
- The pinned Node 20/npm 11 installation can emit the existing transitive
  `@mapbox/jsonlint-lines-primitives` Node >=22 engine warning. The import,
  build, and browser checks used the declared toolchain.
- Missing source coverage, a measured zero, and a technical error remain distinct.
  Uncolored land and zero depth imply no safety guarantee. The map is not a
  property forecast, an event probability, or a permanent shoreline prediction.

## Launch and integrity

For the public fixture, use official Node 20.20.1 and separately selected
npm 11.12.1:

```bash
git clone --branch v0.1.0-rc.1 https://github.com/artemsemdev/SeaRise-Europe.git
cd SeaRise-Europe
npm ci
npm run web:dev
```

For a checked fixture preview, run `npm run web:check` followed by
`npm run web:serve`, then open `http://127.0.0.1:4173/`.
The [README](../../README.md) lists useful routes and browser-check commands.

For a private real-data demo, first provision the verified data/Python environment
and follow the [candidate runbook](../operations/local-demo-candidate.md).
Use official Node 20.20.1 with npm 11.12.1 separately selected on `PATH`, install
with `npm ci`, and complete the runbook's checks from the clean source checkout.
Then use explicit external data and a new candidate directory:

```bash
demo_data_root="/absolute/path/to/local-data/atlas/europe"
demo_candidate="$PWD/.cache/demo-candidates/v0.1.0-rc.1"
npm run demo:preflight -- --data-root "$demo_data_root"
npm run demo:prepare -- --data-root "$demo_data_root" --output "$demo_candidate"
npm run demo:serve -- --data-root "$demo_data_root" --candidate "$demo_candidate"
```

Open `http://127.0.0.1:4181/` in a fresh browser profile. Keep inherited
`SEARISE_*`/`VITE_*` overrides and active `.env` files out of the candidate
checkout; use an explicit compatible `--python` path if necessary.
The launcher checks exact identity, so the previously qualified `rc-2` cannot be
served from the tagged checkout merely because its app tree matches. Preserve
that candidate and its original source checkout. Prepare and verify a new
candidate to demonstrate the tagged version.

## Migration and rollback

This is the first demo prerelease; it introduces no migration of a previously
published stable dataset. Private source inputs stay external and read-only.
Do not deploy the built real-local application to a public static host: it still
requires its private loopback adapter and data.

Stop the launcher with Ctrl+C and wait for its raster child to exit. To return
to an earlier sealed candidate, use a separate clean checkout at the receipt's
exact `sourceRevision`, that revision's pinned tools/dependencies, and the
matching external data identities. Serve the preserved earlier candidate from
that checkout using its explicit path. Git checkout does not restore ignored
inputs; do not edit receipts, mix candidates, or rebuild over the earlier copy.
Use a fresh browser profile. The runbook specifies the complete rollback checks.
